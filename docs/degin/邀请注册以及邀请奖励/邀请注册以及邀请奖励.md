  技术实现方案

  数据库改动

  新增表 aff_rebate_records（返利明细）

  id              主键
  inviter_id      邀请人ID（索引）
  invitee_id      被邀请人ID
  topup_id        充值记录ID（关联）
  topup_quota     充值金额（quota）
  rebate_quota    返利金额（quota）
  rebate_ratio    返利比例快照（如0.1）
  status          状态：pending(待到账) / settled(已到账) / cancelled(已取消)
  created_at      产生时间
  settled_at      到账时间（created_at + 30天）

  User 表新增字段

  AffPendingQuota  int  // 待到账金额（pending 状态汇总）

  后端改动

  1. 系统配置（setting/system_setting.go）
  - AffEnabled — 邀请注册开关（必须邀请码才能注册）
  - AffRebateEnabled — 充值返利开关
  - AffRebateRatio — 返利比例（如 0.1）
  - AffRebateWaitDays — 解冻等待天数（默认30）

  2. 注册校验
  - controller/user.go Register — 开关开启时校验 aff_code 必填且有效
  - controller/oauth.go — OAuth 回调时同样校验

  3. 充值返利
  - 在所有支付成功回调中（Mtbot、支付宝、Epay等），调用 service.CreateAffRebate(userId, topupId, quota) 创建 pending 记录
  - 同时更新邀请人的 AffPendingQuota

  4. 定时结算（service/aff_rebate.go）
  - 后台 goroutine，每小时扫描一次 status=pending 且 settled_at <= now 的记录
  - 转移：AffPendingQuota -= rebate → AffQuota += rebate、AffHistoryQuota += rebate、AffCount（注册时已+1，这里不重复）
  - 状态更新为 settled，写日志

  5. API 端点
  - GET /api/user/aff/stats — 统计概览（4个数字）
  - GET /api/user/aff/invitees — 邀请记录（被邀请人列表+累计贡献）
  - GET /api/user/aff/rebates — 返佣明细（分页）
  - GET /api/admin/aff/report — 管理员统计报表

  6. 历史用户清理
  - 提供 SQL 脚本或管理后台一键清理：删除/解绑 InviterId=0 但需要清理的历史用户（具体策略再细化）

  - 邀请相关开关 + 返利比例 + 解冻天数
