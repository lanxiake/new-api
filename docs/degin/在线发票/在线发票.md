基于当前项目已经支持 Mtbot 支付宝直连充值，要新增"在线开发票"功能，我整理了以下技术方案和服务商选型建议。

  一、业务场景分析

  new-api 是 AI API 网关，用户充值后消费 token，开发票场景：
  - 用户：企业用户充值后需要开具增值税电子普通发票/专用发票用于报销
  - 金额：通常单笔 ¥50-¥5000，频次较高
  - 抬头：企业需要带税号的专用发票，个人需要个人抬头普票
  - 交付：PDF 文件 + 邮件/短信通知

  二、推荐的技术实现路径

  方案 A：第三方开票 API 服务（推荐⭐）

  选型推荐：https://nuonuo.com/open/ —— 航天信息旗下，市场占有率最高，文档完善

  接入要点：
  - 必须有企业营业执照 + 税号 + 税控设备/UKey（个人开发者无法接入）
  - Token 有效期 24 小时，30 天调用上限 50 次（建议动态获取并缓存）

  其他备选：
  - https://blog.csdn.net/a777758/article/details/149801955 — 高并发场景（亿级订单秒级开票）
  - https://www.efapiaoapi.com/blog/ — 中小型企业友好
  - https://www.fpapi.com/ — API 优先、接入门槛低

  方案 B：支付宝原生发票管家集成

  适合已对接支付宝官方支付的商户（不适合 Mtbot 中转方案）：

  参考 https://opendocs.alipay.com/b/03ag5g，需要：
  1. 申请 https://docs.open.alipay.com/396 权限
  2. 在支付时携带 invoice_info 参数：
  {
    "is_support_invoice": "T",
    "invoice_merchant_name": "品牌简称|门店简称",
    "tax_num": "税号"
  }
  3. 调用 alipay.ebpp.invoice.merchantlist.enter.apply 完成商户入驻
  4. 用户在支付宝账单页可直接发起开票请求

  问题：当前项目用的是 Mtbot 第三方代收款，不是商户直连支付宝，无法走此方案。

  三、建议的代码架构

  参考现有 Mtbot 模式，分层实现：

  setting/invoice_config.go        — 发票服务商配置（API key/密钥/税号）
  model/invoice.go                 — 发票订单表（关联充值订单）
  controller/invoice.go            — 发票申请/查询/下载接口
  service/invoice/                 — 发票服务抽象
    ├── nuonuo.go                  — 诺诺实现
    └── interface.go               — 抽象接口（便于多服务商切换）
  web/classic/src/components/invoice/  — 前端发票申请/列表 UI

  数据库设计（关联充值订单）

  CREATE TABLE invoices (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    topup_order_id BIGINT,          -- 关联充值订单
    amount DECIMAL(10,2),            -- 开票金额
    invoice_type VARCHAR(20),        -- normal/special/digital
    buyer_name VARCHAR(255),         -- 抬头
    buyer_tax_num VARCHAR(50),       -- 税号（企业必填）
    buyer_email VARCHAR(255),
    buyer_phone VARCHAR(20),
    status VARCHAR(20),              -- pending/issued/failed/red
    invoice_no VARCHAR(50),          -- 开票服务商返回的发票号
    pdf_url TEXT,                    -- 发票 PDF 链接
    callback_data TEXT,              -- 服务商回调原始数据
    created_at TIMESTAMP,
    updated_at TIMESTAMP
  );

  关键业务流程

  1. 可开票额度计算：用户充值总额 - 已开票总额 - 退款金额
  2. 抬头管理：用户保存常用抬头（参考 https://opendocs.alipay.com/open/396 设计）
  3. 异步开票：调用第三方接口后立即返回 pending，通过 Webhook 回调更新状态
  4. 风控：限制单日开票次数，防止滥用；金额必须等于已确认充值金额

  四、合规要点

  - 税务合规：开票必须基于真实交易，金额必须等于实际收款（参考 https://www.ekuaibao.com/blog/596968.html）
  - 数据安全：买家税号、抬头属于敏感信息，传输需 TLS 1.3+，存储需加密
  - 发票留存：电子发票需保留 10 年（《电子发票管理办法》要求）
  - 红冲处理：用户退款时需提供发票红冲接口

  五、落地步骤建议

  1. 第一阶段（MVP）：
    - 选定诺诺网，申请沙箱账号
    - 实现单一服务商对接，支持普票
    - 前端只暴露给已实名认证的用户
  2. 第二阶段：
    - 支持专票、数电票
    - 抬头管理 + 历史发票列表 + PDF 下载
    - Webhook 回调状态同步
  3. 第三阶段：
    - 抽象多服务商接口，支持切换
    - 红冲/作废流程
    - 自动月结开票（订阅类用户）
