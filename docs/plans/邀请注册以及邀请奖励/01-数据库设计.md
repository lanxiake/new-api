## 一、新增表：`aff_rebate_records`（返利明细）

### 1.1 表结构

```go
// model/aff_rebate_record.go
package model

type AffRebateStatus string

const (
    AffRebateStatusPending   AffRebateStatus = "pending"   // 待到账（30天内）
    AffRebateStatusSettled   AffRebateStatus = "settled"   // 已到账（已加到 AffQuota）
    AffRebateStatusCancelled AffRebateStatus = "cancelled" // 已取消（保留字段，暂不使用）
)

// AffRebateRecord 返利明细记录（每一笔充值返利对应一条）
type AffRebateRecord struct {
    Id           int    `json:"id" gorm:"primaryKey"`
    InviterId    int    `json:"inviter_id" gorm:"index;not null"`             // 邀请人ID（接收返利的人）
    InviteeId    int    `json:"invitee_id" gorm:"index;not null"`             // 被邀请人ID（充值的人）
    TopupId      int    `json:"topup_id" gorm:"index;not null"`               // 关联 TopUp 记录ID
    TopupTradeNo string `json:"topup_trade_no" gorm:"type:varchar(255);index"` // 冗余：充值订单号（便于排查）
    TopupQuota   int    `json:"topup_quota" gorm:"not null"`                  // 充值金额（quota）
    RebateQuota  int    `json:"rebate_quota" gorm:"not null"`                 // 返利金额（quota）
    RebateRatio  float64 `json:"rebate_ratio" gorm:"not null"`                // 返利比例快照（如 0.10）
    Status       string `json:"status" gorm:"type:varchar(32);not null;index"` // pending/settled/cancelled
    CreatedAt    int64  `json:"created_at" gorm:"index;not null"`             // 产生时间戳
    SettleAt     int64  `json:"settle_at" gorm:"index;not null"`              // 应到账时间戳（CreatedAt + 30天）
    SettledAt    int64  `json:"settled_at" gorm:"default:0"`                  // 实际到账时间戳（status=settled 时填充）
}
```

### 1.2 字段说明

| 字段 | 类型 | 索引 | 说明 |
|------|------|------|------|
| Id | int PK | 主键 | 自增 |
| InviterId | int | idx | 邀请人 user_id |
| InviteeId | int | idx | 被邀请人 user_id |
| TopupId | int | idx | 充值记录ID（关联 TopUp.Id） |
| TopupTradeNo | varchar(255) | idx | 冗余订单号，加快查询 |
| TopupQuota | int | — | 充值的 quota 数量 |
| RebateQuota | int | — | 返利 quota = TopupQuota × RebateRatio |
| RebateRatio | float64 | — | 该笔返利使用的比例（快照，配置变更不影响历史记录） |
| Status | varchar(32) | idx | pending/settled/cancelled |
| CreatedAt | int64 | idx | 充值成功时间（Unix 秒） |
| SettleAt | int64 | idx | 计划到账时间（Unix 秒） |
| SettledAt | int64 | — | 实际到账时间（结算后填充） |

### 1.3 索引设计

- `idx_inviter_status_settle`：联合索引 `(InviterId, Status, SettleAt)` — 用户查询自己的待到账列表 + 定时任务扫描待结算
- 单字段索引 `Status`、`SettleAt` 由 GORM 自动建立（已在结构体声明）

### 1.4 跨数据库兼容性检查

| 检查项 | 处理方式 |
|--------|---------|
| `varchar(255)` | SQLite/MySQL/PostgreSQL 均支持 |
| `float64` | GORM 映射为 `DOUBLE`/`REAL`/`double precision`，三库通用 |
| `int64`（时间戳） | 三库通用 |
| 不使用 JSON 列 | ✅ 避免 JSONB |
| 不使用 ENUM | ✅ 用 varchar 存状态 |

## 二、`User` 表字段扩充

### 2.1 新增字段

```go
// model/user.go (在 User 结构体中追加)
AffPendingQuota int `json:"aff_pending_quota" gorm:"type:int;default:0;column:aff_pending_quota"` // 待到账金额（pending 状态汇总，用于前端展示，由结算服务维护）
```

### 2.2 字段语义

- `AffPendingQuota`：用户名下所有 `status=pending` 的 `RebateQuota` 之和
- 不需要每次都从 `aff_rebate_records` 聚合，而是：
  - 创建 pending 时 `+= RebateQuota`
  - 结算（pending → settled）时 `-= RebateQuota`，同时 `AffQuota += RebateQuota`、`AffHistoryQuota += RebateQuota`
- 这是冗余字段，便于前端首页快速展示，**真值仍以表为准**

### 2.3 现有相关字段（不变）

| 字段 | 含义 | 说明 |
|------|------|------|
| AffCode | 邀请码 | 4位随机串，唯一索引 |
| AffCount | 邀请人数 | 注册时 +1 |
| AffQuota | 待使用收益 | 已解冻的返利，可转入 Quota |
| AffHistoryQuota | 历史总收益 | 累计返利总额 |
| InviterId | 邀请人ID | 注册时绑定 |

```go
err := DB.AutoMigrate(

```

### 3.2 User 表新字段迁移

GORM `AutoMigrate` 会自动为已有表添加新列（`AffPendingQuota`），三库均支持。

**SQLite 兼容性**：SQLite 的 `ALTER TABLE ADD COLUMN` 是直接支持的（参见 CLAUDE.md Rule 2），不存在 `ALTER COLUMN` 的限制。

### 3.3 默认值

- `AffPendingQuota` 默认 0（已在 `gorm:"default:0"` 声明）
- 老用户记录加新列后默认值为 0，**符合预期**（历史不补返利）

## 四、查询场景与索引验证

### 场景 1：用户查询自己的「待到账」明细列表（分页，按时间倒序）

```sql
SELECT * FROM aff_rebate_records
WHERE inviter_id = ? AND status = 'pending'
ORDER BY created_at DESC
LIMIT 20 OFFSET 0;
```
**走索引**：`idx_inviter_status_settle`（部分匹配）+ `created_at` 排序需要二次扫描；可接受。

### 场景 2：用户查询「全部返佣明细」（分页）

```sql
SELECT * FROM aff_rebate_records
WHERE inviter_id = ?
ORDER BY created_at DESC
LIMIT 20 OFFSET 0;
```
**走索引**：`InviterId` 单字段索引。

### 场景 3：用户查询「邀请记录」（被邀请人 + 累计贡献返佣）

```sql
SELECT invitee_id, SUM(rebate_quota) AS total_rebate
FROM aff_rebate_records
WHERE inviter_id = ? AND status IN ('pending', 'settled')
GROUP BY invitee_id;
```
然后 JOIN users 表取脱敏用户名。

**走索引**：`InviterId` 索引。

### 场景 4：定时任务扫描待结算（每小时一次）

```sql
SELECT * FROM aff_rebate_records
WHERE status = 'pending' AND settle_at <= ?
LIMIT 500;  -- 分批
```
**走索引**：`(Status, SettleAt)` 联合索引（在 `idx_inviter_status_settle` 中作为前缀仍可用，但更高效的方式是单独建索引或调整顺序）。

**优化建议**：将联合索引顺序调整为 `(Status, SettleAt, InviterId)`，扫描效率更高。具体写法：

```go
type AffRebateRecord struct {
    // ...
    Status   string `gorm:"type:varchar(32);not null;index:idx_status_settle,priority:1"`
    SettleAt int64  `gorm:"index:idx_status_settle,priority:2"`
    InviterId int   `gorm:"index"`  // 单独索引
}
```

### 场景 5：管理员统计报表

```sql
-- 全平台累计返利
SELECT SUM(rebate_quota), COUNT(DISTINCT inviter_id), COUNT(*)
FROM aff_rebate_records
WHERE status = 'settled';

-- 头部邀请人 TOP 10
SELECT inviter_id, SUM(rebate_quota) AS total
FROM aff_rebate_records
WHERE status IN ('pending', 'settled')
GROUP BY inviter_id
ORDER BY total DESC
LIMIT 10;
```

## 五、迁移脚本（可选）

如需在生产环境平滑上线，可手动准备迁移脚本（实际由 GORM AutoMigrate 自动执行，此节仅作参考）：

```sql
-- MySQL 示例
CREATE TABLE IF NOT EXISTS `aff_rebate_records` (
    `id` INT NOT NULL AUTO_INCREMENT,
    `inviter_id` INT NOT NULL,
    `invitee_id` INT NOT NULL,
    `topup_id` INT NOT NULL,
    `topup_trade_no` VARCHAR(255),
    `topup_quota` INT NOT NULL,
    `rebate_quota` INT NOT NULL,
    `rebate_ratio` DOUBLE NOT NULL,
    `status` VARCHAR(32) NOT NULL,
    `created_at` BIGINT NOT NULL,
    `settle_at` BIGINT NOT NULL,
    `settled_at` BIGINT NOT NULL DEFAULT 0,
    PRIMARY KEY (`id`),
    INDEX `idx_inviter_id` (`inviter_id`),
    INDEX `idx_invitee_id` (`invitee_id`),
    INDEX `idx_topup_id` (`topup_id`),
    INDEX `idx_topup_trade_no` (`topup_trade_no`),
    INDEX `idx_status_settle` (`status`, `settle_at`),
    INDEX `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

ALTER TABLE `users` ADD COLUMN `aff_pending_quota` INT DEFAULT 0;
```

## 六、回滚方案

如需回滚：

```sql
DROP TABLE IF EXISTS aff_rebate_records;
ALTER TABLE users DROP COLUMN aff_pending_quota;  -- SQLite 不支持，需要重建表
```

更安全的做法：保留表和字段，仅通过功能开关 `AffRebateEnabled = false` 关闭返利创建。
