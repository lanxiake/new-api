## 二、集成测试（手动 + Postman）

### 2.1 数据准备

```sql
-- 测试用户（在 test 环境）
INSERT INTO users (username, password, role, aff_code) VALUES
  ('inviter01', 'xxx', 1, 'INV1'),
  ('invitee01', 'xxx', 1, NULL);

UPDATE users SET inviter_id = (SELECT id FROM users WHERE username='inviter01')
WHERE username='invitee01';
```

### 2.2 流程测试

**Case A：完整充值返利流程**

1. 管理员后台开启 `AffRebateEnabled = true`，设置 `AffRebateRatio = 0.10`
2. invitee01 通过任一支付方式（如 Epay）充值 100 元 → 到账 5000000 quota
3. 验证：
   - [ ] `aff_rebate_records` 表新增一条 inviter_id=inviter01.id 的记录
   - [ ] `RebateQuota = 500000`
   - [ ] `Status = 'pending'`
   - [ ] `inviter01.aff_pending_quota = 500000`
4. 临时调整 `AffRebateWaitDays = 0` 让定时任务可结算
5. 等定时任务执行（或手动调用 `SettleAffRebates(100)`）
6. 验证：
   - [ ] 记录 Status 变为 `settled`，settled_at 有值
   - [ ] `inviter01.aff_pending_quota = 0`
   - [ ] `inviter01.aff_quota = 500000`
   - [ ] `inviter01.aff_history_quota = 500000`
   - [ ] log 表新增 LogTypeSystem 类型记录

**Case B：邀请注册校验**

1. 开启 `AffRegisterRequired = true`
2. 不带邀请码访问 `/sign-up` 注册 → 应失败
3. 用错误邀请码注册 → 应失败
4. 用 `?aff=INV1` 注册 → 应成功，且 invitee.inviter_id = inviter01.id
5. 关闭开关后，无邀请码也能注册

**Case C：OAuth 注册校验**

1. 开启 `AffRegisterRequired = true`
2. 直接走 GitHub OAuth 注册 → 应失败（带友好提示）
3. 通过 `https://xxx/sign-up?aff=INV1` 跳转后再 GitHub OAuth → 成功

**Case D：充值幂等性**

1. 模拟支付平台重复回调（同一 trade_no）
2. 验证：
   - [ ] 第二次调用 `Recharge*` 直接 return（status=success）
   - [ ] `aff_rebate_records` 仅一条记录
   - [ ] 用户 quota 仅增加一次

**Case E：管理员补单**

1. 创建一个 status=pending 的 TopUp 记录
2. 管理员调用 `AdminCompleteTopUp`
3. 验证：补单完成后也触发返利

**Case F：返利比例变更**

1. `AffRebateRatio = 0.10`，invitee 充值产生记录 A
2. 改为 `AffRebateRatio = 0.20`
3. invitee 再次充值产生记录 B
4. 验证：A 的 RebateRatio=0.10，B 的 RebateRatio=0.20（快照保留）

**Case G：跨数据库**

分别在 SQLite/MySQL/PostgreSQL 执行 Case A-F，确认全部通过。

## 四、性能与并发测试

### 4.1 大量返利记录

1. 准备 10 万条 pending 记录
2. 调用 `SettleAffRebates(500)`
3. 验证：
   - 单批处理不超过 5 秒
   - DB 连接不被耗尽
   - 无死锁

### 4.2 并发充值

模拟 10 个被邀请人同时充值（同一邀请人）：
- 验证 `inviter.aff_pending_quota` 累加正确（无并发覆盖）
- 用 `gorm.Expr("aff_pending_quota + ?", x)` 保证

### 4.3 限流测试

`/api/user/aff/check` 在 1 秒内调用 100 次：
- 部分请求返回 429
- 配置生效
