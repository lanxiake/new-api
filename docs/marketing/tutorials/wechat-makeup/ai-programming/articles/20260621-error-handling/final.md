## 理论：报错信息是写给人看的，不是写给电脑看的

我见过很多初学者对报错的第一反应：屏幕变红，立刻关掉终端。

这是最浪费的操作。那些红字是**电脑在帮你定位问题**——它告诉你文件名、行号、错误类型、错误原因。

<!-- IMAGE:01 type=cover path=images/01-cover.png -->

读懂报错不需要懂编程。你只需要找到三个信息：

**第一步：看最后一行——错误类型和原因**

```
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

- 错误类型：`JSONDecodeError`（JSON 解析失败）
- 原因：`Expecting value`（期待有内容，但第 1 行第 1 列是空的）

**第二步：看 `File "xxx", line N` — 出问题的文件和行号**

```
File "accounting.py", line 23, in load_data
```

- 文件：`accounting.py`
- 行号：第 23 行
- 函数：`load_data`（加载数据的函数）

**第三步：你不需要读中间那些堆栈追踪**

`Traceback (most recent call last):` 后面那一大段是"调用路径"，告诉你程序是怎么一步步走到出错那行的。看最后一个 `File "..."` 就够了，那才是真正出问题的地方。

## 四大类型报错，一张表全搞定

<!-- IMAGE:03 type=infographic path=images/03-error-types.png -->

| 类型 | 长什么样 | 原因 | 怎么办 |
|------|---------|------|--------|
| **环境错误** | `command not found: python` / `ModuleNotFoundError` | Python 没装好，或缺少依赖包 | 把报错截图给 AI，说明你的系统（Windows/Mac）|
| **语法错误** | `SyntaxError: invalid syntax` | 代码写错了，少个括号/冒号等 | AI 写的代码不该有，直接把完整报错给 AI |
| **运行时崩溃** | `KeyError` / `TypeError` / `FileNotFoundError` | 程序跑起来了但某步出错 | 说清楚"做了什么操作"+"出现了什么报错" |
| **逻辑错误** | 不报错，但结果不对 | AI 理解偏差 | 描述"期望结果是什么，实际得到的是什么" |

最难搞的是最后一种——**逻辑错误不报错**，你得自己发现。这就是"测试"存在的意义。

## 实操：亲手修好三个典型报错

### 准备工作

用上篇的记账工具（`accounting.py`）来练习。如果你没做，先把这段粘给 Claude Code 生成一个简单版本：

```
帮我生成一个简单的命令行记账工具 accounting.py，功能：记录收支到 data.json，显示余额。
纯 Python 标准库，不用第三方包。
```

---

### 报错 1：FileNotFoundError（文件找不到）

**制造报错**：先把 `data.json` 删掉，然后在程序里选"查看账单"。

你可能会看到：
```
FileNotFoundError: [Errno 2] No such file or directory: 'data.json'
```

**把这段描述给 AI：**

```
程序报错了，报错信息如下：
FileNotFoundError: [Errno 2] No such file or directory: 'data.json'

情况说明：我把 data.json 删掉了之后，运行程序选"查看账单"出现了这个报错。

期望：没有 data.json 时，程序应该自动创建一个空文件，而不是崩溃。

请只修复这个问题，不要改动其他功能。
```

AI 会给你修复方案，通常是加一个"如果文件不存在就创建"的判断。

---

### 报错 2：JSONDecodeError（数据损坏）

**制造报错**：打开 `data.json`，把里面改成乱码，然后运行程序。

你会看到：
```
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)
```

**给 AI 的描述：**

```
程序报错，报错信息：
json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0)

情况：我手动修改了 data.json 导致文件内容损坏。

期望：程序检测到 data.json 内容损坏时，提示"数据文件损坏，已重置为空"，
然后以空数据启动，不要崩溃。

请只修复数据加载部分的错误处理。
```

---

### 报错 3：逻辑错误（结果不对但不报错）

**制造问题**：记录一笔"支出 30 元"，查看余额，看看是显示 `-30` 还是 `30`。

如果显示 `30`（正数），说明 AI 没有正确处理支出的符号。

**给 AI 的描述：**

```
程序有个逻辑问题，不报错但结果不对：

我记录了一笔"支出 30 元"，查看余额时显示 +30，应该显示 -30。

期望：
- 余额 = 所有收入之和 - 所有支出之和
- 余额为正时显示绿色 +数字，余额为负时显示红色 -数字

请修复余额计算逻辑。
```

这三个练习走完，你已经掌握了处理报错的核心方法。

## 成果

<!-- IMAGE:04 type=screenshot path=images/04-fixed.png -->

做完这三个修复，你的记账工具变得更健壮：
- 不会因为文件不存在就崩溃
- 不会因为数据损坏就无法启动
- 余额计算正确

这些修复叫做**错误处理（Error Handling）**——预判用户可能犯的错，让程序优雅应对而不是直接崩溃。好的程序和差的程序，差距很大一部分就在这里。

## 避坑：报错处理的三个误区

**误区 1：把整个文件代码粘给 AI，说"帮我修"**

AI 看到几百行代码，修的时候容易改乱。正确做法：**只粘报错信息 + 操作步骤**，不需要粘代码——AI 知道在哪里改。

**误区 2：报错修好了，不验证，继续往前走**

修好一个报错之后，**必须重新测试**：不仅测刚才报错的操作，还要测一遍其他功能，确认没有被改坏。AI 有时候修 A 会顺带影响 B。

**误区 3：同一个报错 AI 修了两次没改好，继续描述**

如果修了两次还不对，大概率是你的描述不够精确，或者 AI 对问题的理解有偏差。这时候：换一种方式描述，或者直接说"你之前的两次修复都没有解决问题，问题还是……"，让它重新分析。

## 本篇小结

三句话，可以截图保存：

1. **报错是电脑在告诉你哪里出了问题**，不是让你放弃的信号——看最后一行，找文件和行号
2. **报错四类型**：环境问题、语法错误、运行时崩溃、逻辑错误——前三类 AI 直接能修，第四类要你自己发现
3. **把报错给 AI 的格式**：报错信息 + 操作步骤 + 期望结果，三件事说清楚，AI 修准率大幅提升
