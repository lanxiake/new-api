## 理论：一个项目从想法到能用，经历了什么

做项目不是"跟 AI 说一句话然后等它写完"。你和 AI 的协作是一个来回的过程。

<!-- IMAGE:01 type=cover path=images/01-cover.png -->

**一个项目的完整流程是这样的：**

```
想法 → 拆需求 → AI 实现 → 你测试 → 发现问题 → AI 修复 → 再测试 → 满意为止
```

听起来像在兜圈子？这就是软件开发的真相。没有哪个程序是"一次写完完美运行"的——无论是 AI 写的还是人写的。

**你在这个流程里扮演的角色是"测试员 + 产品经理"：**
- AI 写代码
- 你运行，验证功能对不对
- 发现问题，描述清楚，让 AI 修

这个节奏你会越来越熟练。30 篇之后，你甚至会觉得"AI 能一次写对"才是异常。

## 实操：30 分钟做出记账小工具

### 目标

做一个**命令行记账工具**，功能：
- 记录每笔收支（金额 + 类别 + 备注）
- 查看所有记录
- 查看总余额
- 数据存在本地文件，重启不消失

### 第一步：建好项目目录，写 CLAUDE.md

打开终端，建文件夹：

```bash
cd Desktop
mkdir accounting-tool
cd accounting-tool
```

启动 Claude Code：

```bash
claude
```

进入之后，先让 AI 建一个 CLAUDE.md：

```
请帮我在当前目录创建 CLAUDE.md 文件。

项目信息：
- 项目名称：个人记账小工具
- 功能：命令行记账，支持记录收支、查看记录、查看余额，数据保存到本地 JSON 文件
- 技术：纯 Python，不使用任何第三方库
- 规范：
  - 代码注释用中文
  - 每次修改前先说明方案
  - 不要删除已有功能
  - 遇到报错先分析原因
```

AI 会帮你创建好这个文件。

### 第二步：描述完整需求，让 AI 一次给出骨架

需求描述是成败关键。用第02篇讲的"做·有·存·用"框架：

```
帮我做一个命令行记账工具，文件名 accounting.py。

【做什么】
程序启动后显示菜单，用户选择操作：
1. 记录一笔账（输入金额、类型、备注）
2. 查看所有账单
3. 查看当前余额（所有收入减去所有支出）
4. 退出程序

【有什么数据】
每条记录包含：
- date：记录时间（自动获取当前时间）
- type：类型（只允许填"收入"或"支出"）
- amount：金额（正数，单位元）
- note：备注（可选）

【存在哪里】
数据存在当前目录的 data.json 文件里。
程序每次启动时自动读取已有数据；没有文件时自动创建。

【用户怎么用】
- 运行：python accounting.py
- 全程中文提示
- 输入错误时给出友好提示，不要崩溃

技术要求：纯 Python 标准库，无第三方依赖。
```

把这段提示词完整复制进去，等 AI 写完。

### 第三步：运行，看效果

AI 写完后，在当前目录运行：

```bash
python accounting.py
```

<!-- IMAGE:03 type=screenshot path=images/03-running.png -->

正常情况下，你会看到一个菜单。试试：
1. 选 1，记录一笔"收入，5000，工资"
2. 选 1，再记录一笔"支出，30，午餐"
3. 选 2，查看所有记录
4. 选 3，看余额

如果程序能按上面的步骤跑下来——**恭喜，你的第一个真实项目运行起来了。**

### 第四步：验证数据是否真的保存了

按 4 退出程序，然后重新运行 `python accounting.py`，选 2 查看记录。

如果你刚才记录的账单还在——**数据持久化成功**。

这很重要。很多教程里的"记账工具"关了就消失，跟真实需求有本质差距。你做的这个，数据真的存下来了。

### 第五步：发现问题，让 AI 修

跑完基础流程，你多半会发现些不满意的地方。这很正常——这就是"测试"环节。

常见问题举例，以及怎么让 AI 修：

**问题1：输入金额时输了文字，程序崩溃了**

```
程序有个问题：在输入金额时，如果我输入"三十元"这种文字，程序直接报错退出了。
请修复：输入非数字时，提示"请输入数字金额"，让用户重新输入，不要崩溃。
```

**问题2：想看"只看收入"或"只看支出"**

```
请在查看账单菜单里增加过滤功能：
- 选 2 查看账单后，可以选择查看"全部/只看收入/只看支出"
- 过滤后显示对应记录，并在底部显示该筛选条件下的小计金额
```

**关键原则**：描述问题时，说清楚"什么情况下""出现什么现象""期望是什么"。越具体，AI 修得越准。

## 避坑：第一次做项目最常见的三个坑

**坑 1：需求说了一半，AI 猜了另一半**

"给我做个记账工具"——AI 会做，但和你想的不一样。需求要说清楚四件事：做什么、有什么数据、存在哪、怎么用。本篇的提示词就是这个结构，照着写就行。

**坑 2：发现问题，直接叫 AI "重写"**

重写容易让 AI 把能用的地方也改掉。正确做法：**只描述出问题的那个功能**，不要让它改动其他部分。用"只修复 X，不改动其他"明确限定范围。

**坑 3：AI 改一次没改对，就说"你怎么这么笨"**

没用。把实际的报错信息或错误行为完整描述给 AI：

```
我测试了你的修复，输入"abc"时不报错了，但输入"-100"这种负数时没有拦截，
仍然记录进去了。请修复：金额只允许正数，输入负数或零时提示重新输入。
```

精准描述 = 精准修复。

## 本篇小结

三句话，可以截图保存：

1. **做项目 = 需求 → AI 实现 → 你测试 → 修复 → 再测试**，这个循环是正常的，不是失败
2. **需求描述用"做·有·存·用"四步**，比"帮我做个记账工具"能得到好 10 倍的结果
3. **发现问题描述现象，不要叫 AI 重写**——精准描述才能精准修复
