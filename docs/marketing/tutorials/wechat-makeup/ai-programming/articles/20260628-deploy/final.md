本地跑起来了，手机上也能访问了。

但你发给外地的朋友让他试试——他访问你的 IP 地址，打不开。

因为那个 IP 是你家局域网的内网地址，出了你家 WiFi 就无效了。

**你的程序还在你的电脑上。要让全世界任何人都能访问，你需要把它部署到"云"上。**

这一篇讲"部署"——把程序从你的电脑搬到互联网上，拿到一个任何人都能打开的链接。

## 理论：本地 vs 线上，到底差在哪

你的程序现在跑在你的电脑上，有以下限制：

- 你的电脑一关机，程序就挂了
- 只有和你在同一 WiFi 里的设备才能访问
- IP 地址不固定，每次重连网络可能变化

**"部署到云"就是把你的程序搬到一台 24 小时开机的服务器上运行**，这台服务器有一个固定的公网 IP，通过域名可以让全球任何人访问。

<!-- IMAGE:01 type=cover path=images/01-cover.png -->

**免费部署的三个主流选择：**

| 方案 | 适合什么 | 免费额度 | 难度 |
|------|---------|---------|------|
| **Railway** | Python/Flask 后端 + 数据库 | 每月 $5 额度 | ⭐⭐ |
| **Render** | Python/Node 全栈 | 750 小时/月（会休眠） | ⭐⭐ |
| **Vercel** | 纯前端 / Serverless | 无限次请求 | ⭐ |

我们用 **Railway**——对 Python Flask 支持最好，配置最简单，不会无缘无故休眠。

## 实操：把记账工具部署到 Railway

### 第一步：准备代码——让程序"云端就绪"

云端运行和本地有几个不同：端口不能写死、依赖需要声明、数据存储需要考虑持久化。

让 AI 帮你做准备：

```
我要把这个 Flask 记账工具部署到 Railway。请帮我做以下修改：

1. 修改启动端口：
   从 app.run(port=5000) 改为 app.run(port=int(os.environ.get('PORT', 5000)))
   这样 Railway 可以自动分配端口

2. 创建 requirements.txt 文件，内容：
   flask
   gunicorn
   （gunicorn 是生产环境用的 Web 服务器，Railway 需要用它启动程序）

3. 创建 Procfile 文件（无后缀名），内容：
   web: gunicorn accounting:app
   （告诉 Railway 用什么命令启动程序）

4. 数据存储说明：
   Railway 的文件系统是临时的，重新部署后 data.json 会消失。
   目前先保持用 JSON 文件（用于演示），后续篇章会接入真正的数据库。

请完成上述修改，然后告诉我每个文件的内容。
```

### 第二步：把代码推送到 GitHub

Railway 从 GitHub 拉取代码，所以先要把代码放到 GitHub 上。

让 AI 帮你初始化 Git 仓库：

```
请帮我在当前目录初始化 Git 仓库，并创建 .gitignore 文件（排除 data.json、__pycache__、*.pyc），
然后告诉我把代码推到 GitHub 的完整步骤（我还没有 GitHub 账号也可以告诉我怎么注册）。
```

AI 会给你完整的步骤，包括注册 GitHub、创建仓库、推送代码的每一条命令。

### 第三步：在 Railway 上部署

1. 打开 `railway.app`，用 GitHub 账号登录
2. 点"New Project"→"Deploy from GitHub repo"
3. 选你刚推送的仓库
4. Railway 会自动检测 Python + Procfile，开始部署
5. 等 2-3 分钟，看 Deployments 标签里状态变绿

### 第四步：拿到可分享的链接

部署成功后，Railway 会给你一个域名，格式类似：
`your-app-name-production.up.railway.app`

<!-- IMAGE:03 type=screenshot path=images/03-deployed.png -->

把这个链接发给朋友，他们不需要任何配置，打开浏览器就能用你的记账工具。

**你做到了——你的程序上线了。**

### 第五步：更新程序

以后每次改了代码，只需要：

```bash
git add .
git commit -m "更新：描述你改了什么"
git push
```

Railway 会自动检测到 GitHub 有新代码，自动重新部署。大概 2-3 分钟后，线上版本就更新了。

## 避坑：部署最常见的三个问题

**问题 1：部署失败，看不懂日志**

Railway 的 Logs 标签里有部署日志。把错误日志的最后 20 行复制给 AI：

```
我在 Railway 部署 Flask 应用，部署失败了，日志如下：
[粘贴日志]
请告诉我是什么原因，怎么修复。
```

**问题 2：data.json 数据丢失了**

重新部署后文件系统会重置——这是预期行为，不是 bug。这就是为什么真实应用需要数据库（第12篇解决这个问题）。现在可以用 Railway 的持久化存储作为临时方案：

```
我在 Railway 部署，每次重新部署后 data.json 就消失了。
请告诉我怎么在 Railway 上挂载持久化卷（Persistent Volume）来保存这个文件。
```

**问题 3：免费额度用完了**

Railway 每月有 $5 免费额度，小应用足够用。用完了有两个选择：
- 换 Render（有免费套餐，但会休眠）
- 或者等下一篇，接入云数据库，成本更可控
