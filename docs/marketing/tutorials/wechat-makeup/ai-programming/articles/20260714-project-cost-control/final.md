这句话其实问了两件事，也正是很多人卡在"学完"和"做成"之间的两道坎：

1. **会做小玩具，不会做真东西**——单个功能能跑，但不知道怎么把需求、架构、写代码、报错、界面、数据库、API 这些拼成一个完整产品。
2. **不敢花钱，也算不清账**——总担心 AI 调用很贵，又说不清到底贵在哪、怎么省。

今天是这个系列的**最后一篇**。我们不讲新概念了，而是把前 13 篇学的所有东西**综合运用一次**，亲手做出一个**副业级的小工具**，然后——**把这个工具一个月要花多少钱，算到小数点后面给你看。**

## 理论：花钱这件事，AI 编程里到底贵在哪

前面 13 篇我们一直在"省着用"，今天得把这层窗户纸捅破：**AI 编程的钱，主要花在"调用大模型"上。**

<!-- IMAGE:02 type=infographic path=images/02-cost-structure.png -->

你可以这样理解：

> **大模型就像请人干活，请的人不同，价钱差好几倍。**

- 让 AI 帮你**写一段简单文案、做个分类判断**——这是"跑腿小活"，请个**便宜麻利的实习生**就够了（便宜的小模型）。
- 让 AI 帮你**重构一整个项目、解决疑难报错**——这是"硬骨头"，才值得请**资深专家**（贵的大模型）。

新手最常见的浪费，就是**不管什么活都请专家**——用最贵的模型去干最简单的事，账单自然下不来。

**省钱的第一原则，就是"看活派人"：简单任务用便宜模型，复杂任务才上贵模型。** 这就是"模型选择"。

### 那"中转"又是省在哪？

直接去各家官网买模型，有三个痛点：国内网络访问不稳、每家都要单独注册付费、用多少不透明。

> **中转站就像一个"话费充值 + 多卡合一"的平台。** 你充一次值，就能用上多家的模型，按实际用量扣费，每一笔花在哪、花了多少，账单清清楚楚。

我们系列一直用的 **LLM-Link 中转**，正是干这个的：一个 Key 接通多个模型、按量计费、网络稳定。对要算账、要省钱的副业场景，这比订阅制更划算——**没用就不花钱，用多少算多少。**

## 实操：做一个「AI 小红书文案生成器」

光说不练假把式。我们现在做一个真能拿去用的副业工具：**输入一个产品或主题，它自动生成几条小红书风格的文案，并把历史记录存下来。**

这个工具会**一次用上你学过的全部四层**：

| 层 | 这个工具里负责什么 | 对应你学过的篇目 |
|----|------------------|----------------|
| 前端（Vue） | 输入框 + "生成"按钮 + 文案展示 | 第10篇 网页界面 |
| 后端（Python） | 接收请求、调模型、处理结果 | 第08篇 第一个项目 |
| 数据库（MySQL） | 保存每次生成的历史 | 第12篇 数据库 |
| API（大模型） | 真正"写文案"的能力 | 第13篇 API |

### 第一步：把整个需求一次说清楚

打开 Claude Code（`cd` 进一个空文件夹，输入 `claude` 启动），把这段提示词**整段复制**进去：

```
我要做一个「AI 小红书文案生成器」网页工具，技术栈用 Vue + Python(FastAPI) + MySQL。

功能需求（做·有·存·用 四步）：
- 做什么：用户在网页输入一个产品名或主题，点"生成"，得到 3 条小红书风格文案（带 emoji、标题党、痛点+种草结构）
- 有什么：一个简洁的输入页 + 生成结果卡片展示 + 一个"历史记录"列表
- 存什么：每次生成的 输入主题、生成文案、使用的模型、消耗，都存进 MySQL
- 怎么用：本地能跑起来，浏览器打开就能用

技术约束：
- 调用大模型走 OpenAI 兼容接口，base_url 和 api_key 用环境变量 LLM_LINK_BASE_URL / LLM_LINK_API_KEY
- 模型先用便宜快的（如 deepseek-chat 或 glm-4-flash），把模型名也设成环境变量 MODEL_NAME 方便切换
- 先做最小可用版本（MVP），不要过度设计

请你：
1. 先列出项目文件结构和每个文件的职责，让我确认
2. 我确认后，再逐个文件生成代码
3. 最后告诉我怎么建数据库表、怎么启动前后端
```

> **划重点**：注意这段提示词里，我们用了第02篇的「做·有·存·用」四步框架描述需求，用了第06篇的三层架构，把模型名和密钥设成环境变量（方便后面切换模型省钱）。**这就是"综合运用"——你不是在写代码，你是在用学过的常识指挥 AI。**

AI 会先给你一份文件结构（前端 Vue、后端 FastAPI、数据库建表 SQL）让你确认。确认后它逐个生成代码。

### 第二步：跑起来

跟着 AI 给的启动说明做（通常就三件事）：

```bash
# 1. 建数据库表（把 AI 给的建表 SQL 复制进 MySQL 执行）
# 2. 启动后端
python -m pip install fastapi uvicorn openai pymysql
uvicorn main:app --reload

# 3. 启动前端（另开一个终端）
cd frontend && npm install && npm run dev
```

报错了不要慌——这是**正常流程**（还记得第09篇吗）。把报错原文整段复制给 AI，加一句"这个报错怎么解决"，它会带你修。

<!-- IMAGE:03 type=screenshot path=images/03-tool-running.png -->

### 第三步：换个模型，对比成本（关键一步）

工具跑通后，做一件大多数教程不会教你的事：**换模型，看账单。**

因为我们把模型名设成了环境变量 `MODEL_NAME`，所以切换只需改一个值，不用动代码：

```
# .env 文件里
MODEL_NAME=glm-4-flash      # 便宜快，适合批量生成文案
# MODEL_NAME=deepseek-chat  # 稍贵一点，文案质量更高
# MODEL_NAME=claude-haiku   # 海外模型，中文也不错
```

同一句"帮我给一款桂花香氛蜡烛写小红书文案"，分别用便宜模型和贵模型各生成一次，你会发现：**对"写文案"这种任务，便宜模型的效果已经够用了，没必要上最贵的。** 这就是省钱的实战判断。

## 成果：一个能用的工具 + 一份你自己的成本对照表

跑完上面三步，你手里就有了一个**真能拿去接活、甚至挂出来收费**的小工具。

更重要的是第二样东西——**成本对照表**。打开 LLM-Link 后台的用量账单，你会看到每次调用的真实消耗。我们团队实测，这个文案工具的成本大致是这样（仅供参考，以实际账单为准）：

<!-- IMAGE:04 type=infographic path=images/04-cost-table.png -->

| 模型 | 每次生成约消耗 | 单次成本 | 生成 1000 次 | 适用场景 |
|------|--------------|---------|------------|---------|
| glm-4-flash | 约 1.5K tokens | 约 ¥0.001 | 约 ¥1～2 | 批量文案、首选 |
| deepseek-chat | 约 1.5K tokens | 约 ¥0.003 | 约 ¥3～5 | 质量要求更高时 |
| 顶级大模型 | 约 1.5K tokens | 约 ¥0.06+ | 约 ¥60+ | 这种任务**没必要用** |

把这张表读三遍，你会得到一个反直觉但极其重要的结论：

> **同一个工具，模型选对了，成本能差几十倍。** 一个月生成 1000 条文案，用对模型只要几块钱，用错模型要几十上百块。**省钱的秘诀不是"少用 AI"，而是"看活派人"。**

这份表，就是你从"不敢花钱"到"算得清账"的分水岭。

## 避坑：副业工具最容易栽的三个跟头

**坑 1：一上来就追求"高级"，用最贵的模型**

新手总觉得贵的就是好的。但对文案生成、分类、摘要这类任务，便宜模型完全够用。**先用便宜模型把东西跑通，只在效果明显不够时才升级。** 把钱花在刀刃上。

**坑 2：密钥写死在代码里**

把 api_key 直接写进代码，是大忌——既不安全，也没法切换模型省钱。**一定用环境变量**（`.env` 文件），这也是为什么我们提示词里特意强调这一点。

**坑 3：只做"能跑"，不做"能用"**

很多人工具跑通就停了。但副业级的东西，还差最后一公里：起个好名字、加个简单说明、部署上线拿到链接（第11篇）。**能跑是 60 分，能让别人打开链接就用，才是 80 分。**
