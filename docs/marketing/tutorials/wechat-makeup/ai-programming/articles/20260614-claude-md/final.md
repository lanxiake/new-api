# 第07篇：给 AI 一份工作手册——CLAUDE.md 怎么写

> 适合读者：开始做正式项目、发现 AI 每次对话都"忘事"的读者
> 阅读时间：约 12 分钟

---

<!-- IMAGE:01 type=cover prompt-ref=images/prompts.md#cover -->

你有没有遇到过这个场景：

上次你花了半小时，好不容易跟 AI 说清楚了你的项目——用 Python 写后端、数据库用 MySQL、代码注释要用中文……

第二天打开 Claude Code，新建对话，打了个"继续帮我做项目"——

**AI 一脸懵：什么项目？你用什么技术栈？有什么要求？**

从头说，又花半小时。

然后第三天，又忘了。

这不是 AI 变蠢了，这是 AI 的**天然限制：它没有跨对话的长期记忆**。每次新建对话，就是一张白纸。

但这个问题有个优雅的解法，而且很简单——

**给它写一份工作手册，放在项目里，让它每次自动读取。**

这个文件叫 `CLAUDE.md`。

## 理论一：AI 为什么会"失忆"？

要解决问题，先搞懂原因。

<!-- IMAGE:02 type=infographic path=images/02-context-memory.png -->

AI 的工作方式是这样的：**每次对话，它只能看到这次对话里说过的内容**，看不到上次对话，也看不到你的脑子。

用一个类比：

> AI 就像一个**每天失忆的实习生**。每天早上来上班，什么都不记得了，需要你从头交代任务。
>
> 如果你每天都口头交代，很累；但如果你给他写一份"新人须知"贴在工位上，他每天来了先看一遍，就能立刻上手——这就是 CLAUDE.md 的作用。

技术上说，Claude Code 每次启动时，会**自动读取项目根目录里的 `CLAUDE.md` 文件**，把它的内容加进对话的"背景知识"里。AI 每次开始工作前都先看了这份文件，就像读了一遍工作说明书。

---

## 理论二：CLAUDE.md 里该写什么？

一份好的 CLAUDE.md 回答三个问题：

**① 这是什么项目？**（让 AI 不用每次问"你要做什么"）

**② 用什么技术？**（避免 AI 自作主张换技术栈）

**③ 有什么规矩？**（代码风格、注释语言、禁止行为等）

<!-- IMAGE:03 type=infographic path=images/03-claudemd-structure.png -->

**不该写什么：**
- 每一行代码的细节（太多了 AI 读不完）
- 会变化的内容（比如"今天要做登录功能"这种，放在对话里说就好）
- 没有意义的废话（"请认真工作"这种 AI 会忽略）

## 实操：写一份真实可用的 CLAUDE.md

现在我们直接动手。这是一份**记账小工具项目**的 CLAUDE.md 模板，你可以直接复制，改成自己的项目：

**第一步：打开终端，进入你的项目文件夹**

```bash
cd Desktop/ai-practice
```

**第二步：让 AI 帮你生成 CLAUDE.md**

启动 Claude Code（输入 `claude` 回车），把这段提示词复制进去：

```
请帮我创建一个 CLAUDE.md 文件，放在当前目录。

这是我的项目信息：
- 项目名称：个人记账小工具
- 功能：记录每笔收支（金额/类别/备注），查看月度统计，数据永久保存
- 技术栈：
  - 后端：Python（Flask 框架）
  - 前端：Vue 3
  - 数据库：MySQL
- 我的要求：
  - 代码注释用中文
  - 变量名用英文
  - 每次修改前先告诉我你打算怎么改，我确认后再动手
  - 遇到报错先分析原因，不要直接乱改代码
  - 不要删除我已有的功能，只添加新的

请用 Markdown 格式写，结构清晰，语言简洁。
```

AI 会给你生成一份 CLAUDE.md。它会直接在你的项目文件夹里创建这个文件。

<!-- IMAGE:04 type=screenshot path=images/04-claudemd-result.png -->

**第三步：验证它起效了**

关闭当前对话（输入 `/exit`），重新启动 Claude Code（再次输入 `claude`）。新对话开始后，输入：

```
你对这个项目了解多少？
```

如果 AI 能准确说出你的项目名称、技术栈和规则——**CLAUDE.md 起效了**，它已经"记住"了你的项目。

## 一份真实的 CLAUDE.md 长什么样？

这是按上面步骤生成出来的一份示例，供你参考：

```markdown
# 个人记账小工具

## 项目概述
记录每笔收支并统计月度数据的个人工具。
功能：添加收支记录（金额/类别/备注）、查看月度统计报表、数据持久化存储。

## 技术栈
- 后端：Python 3.x + Flask
- 前端：Vue 3 + Vite
- 数据库：MySQL 8.0

## 开发规范
- 代码注释统一使用中文
- 变量名、函数名使用英文（小写下划线风格）
- 每次修改前先说明方案，等待确认后再执行
- 遇到报错先分析根本原因，不要用临时方案糊弄

## 禁止行为
- 不得删除或重命名已有功能模块
- 不得更换技术栈（除非我明确提出）
- 不得在没有说明的情况下修改数据库表结构
```

不长，但够用。

---

## 进阶：CLAUDE.md 可以有多个

随着项目变大，你可以在不同子文件夹里放不同的 CLAUDE.md：

- 项目根目录：整体规范
- `backend/`：后端专用说明
- `frontend/`：前端专用说明

Claude Code 会**自动读取当前目录及所有上级目录**的 CLAUDE.md，层层叠加。

但对于初学者，**一个根目录的 CLAUDE.md 就完全够用了**，别想太复杂。

---

## 避坑：CLAUDE.md 的三个常见错误

**错误 1：写得太长**

有人把整个项目文档都塞进去，几千字。AI 不是不读，是读了等于没读——内容太多，关键规则被稀释了。**保持在 300 字以内，只写最重要的规则。**

**错误 2：写"做什么"而不写"怎么做"**

"帮我做一个好用的记账工具"——这是目标，不是规则。AI 不会把它当约束。要写的是**具体行为规范**，比如"每次修改前先告诉我方案"。

**错误 3：从不更新**

项目进展会改变规则。比如你后来换了数据库、或者新增了某个限制。CLAUDE.md 需要**随项目演进而更新**，否则 AI 会按旧规则行事。

## 本篇小结

三句话，可以截图保存：

1. **AI 每次对话都会"失忆"**，这是天然限制，不是 bug
2. **CLAUDE.md = AI 的工作手册**，放在项目根目录，每次启动自动读取
3. **只写三件事**：项目是什么、用什么技术、有什么规矩——简短、具体、可执行
