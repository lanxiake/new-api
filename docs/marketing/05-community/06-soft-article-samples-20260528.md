## 范文一：A类干货（公众号版）

**标题**：《Claude extended thinking到底好不好用？我测了10个真实场景，结论来了》

**类型**：A类干货，不提中转站

**适合发布时间**：内容日历第1周

---

用了Claude extended thinking差不多两个月，今天把真实测试结果写出来，说说哪些场景真的有用，哪些纯属浪费token。

结论先说：**复杂逻辑推理场景效果显著，简单任务完全不需要开**。

---

### extended thinking是什么

简单说：开启这个功能后，Claude在正式回答之前会先自己"想一遍"，把推理过程放在一个隐藏的thinking block里，然后再输出最终答案。

官方说法是可以提升复杂任务的准确率，代价是消耗更多token和更长的等待时间。

API调用方式：

```python
response = client.messages.create(
    model="claude-3-7-sonnet-20250219",
    max_tokens=16000,
    thinking={
        "type": "enabled",
        "budget_tokens": 10000  # 思考过程最多用多少token
    },
    messages=[{"role": "user", "content": "你的问题"}]
)
```

Claude Code用户不用额外配置，3.7版本默认支持，直接用就行。

### 我测试的10个场景

**场景1：复杂算法设计** ✅ 效果显著

让它设计一个分布式限流算法，要求支持滑动窗口、Redis持久化、多节点同步。

不开thinking：给了一个基础的令牌桶方案，没考虑多节点同步问题。

开thinking（budget_tokens=8000）：方案里自动考虑了网络分区场景、时钟漂移问题，还给出了降级策略。

实测结论：设计类问题提升明显，thinking过程里能看到它在自己质疑自己的方案。

---

**场景2：代码Debug** ✅ 有提升

一段300行的Go代码，有一个隐藏的并发race condition。

不开thinking：找到了表面上的3个问题，没发现race condition。

开thinking：花了更长时间，但成功定位了race condition，并解释了触发条件。

---

**场景3：数学证明** ✅ 效果显著

让它证明一个关于图论的定理（非教科书题目）。

不开thinking：证明过程有逻辑跳跃，两步推导之间有gap。

开thinking：证明完整，thinking block里能看到它走了几条错路然后自己否定了。

---

**场景4：简单代码生成** ❌ 没必要开

写一个HTTP请求的工具函数，加错误处理和重试。

不开thinking：完全够用，30秒出结果。

开thinking：多等了15秒，结果基本一样。

结论：简单任务开thinking纯属浪费。

---

**场景5：文档生成** ❌ 没必要开

根据代码生成接口文档。

结论同上，thinking对这类格式化输出没有帮助。

---

**场景6：架构方案设计** ✅ 效果显著

给定业务需求，设计微服务拆分方案。

开thinking后，它在thinking block里会先列出几种方案，然后分析各自的trade-off，最终给出推荐方案并说明理由。

不开thinking的方案通常只有一个选项，没有对比分析。

---

**场景7：代码审查** ✅ 有提升，但不如预期

对一段复杂业务逻辑做code review，开thinking后确实发现了更多潜在问题，但提升幅度没有算法设计场景那么大。

---

**场景8：翻译** ❌ 没必要开

---

**场景9：写作/文案** ❌ 基本没差别

---

**场景10：复杂SQL优化** ✅ 有提升

涉及多表join和子查询的SQL，开thinking后的优化方案更完整，考虑了索引策略和执行计划。

---

### 总结：什么时候开，什么时候不开

| 场景 | 建议 | 理由 |
|------|------|------|
| 算法/系统设计 | **开，budget_tokens 8000+** | 需要多步推理，收益明显 |
| 复杂Debug | **开，budget_tokens 5000** | 隐藏bug需要深度分析 |
| 架构方案 | **开，budget_tokens 10000** | 需要对比多个方案 |
| 数学/逻辑推理 | **开** | 推理准确性提升显著 |
| 代码生成（简单） | **不开** | 浪费时间和token |
| 文档/翻译/写作 | **不开** | 基本没有提升 |
| Code Review（一般复杂度） | **视情况** | 复杂业务逻辑开，普通代码不开 |

---

### token消耗参考

thinking block本身会消耗token，而且这部分token**不走prompt caching**。

实测数据：
- budget_tokens=8000，实际thinking消耗约4000-7000 tokens（不一定用满）
- 同等任务，开thinking后总token消耗增加50%-200%

建议：只在真正需要深度推理的任务上开，日常Claude Code写代码不必默认开启。

---

3个月前我开始把Claude Code当主力开发工具，今天把账单完整公开，也分享一下我是怎么把成本控制住的。

先说结论：**现在每月花¥150-200左右，相比官方Max订阅省了一半以上。**

---

### 我的使用强度

先说使用强度，省得对不上号：

- 每天使用Claude Code约3-4小时
- 主要任务：Go后端开发，偶尔做架构设计
- 模型选择：90%用claude-opus-4-7，10%用claude-3-5-haiku
- 有开启Prompt Caching（重复上下文场景命中率约65%）

这个强度属于**重度用户**。轻度用户（每天1小时以内）成本会低很多。

---

### 三个月的成本演变

**第一个月：官方Pro订阅**

$20/月，约¥145。

用了两周，每天下午3-5点固定触发rate limit，写代码写到一半断掉，体验很差。而且$20的额度不够重度使用，经常月底前就用完了。

放弃原因：有速率限制 + 不够用。

---

**第二个月：官方API直连**

切换到官方API按量计费，没有速率限制，用多少付多少。

问题来了：

1. 绑的是朋友的Visa卡，每次充值都要麻烦人家
2. 汇率 + 手续费合计损耗约7%
3. 网络偶尔不稳定，Claude Code中途断连

那个月账单：$163，折合人民币约¥1250（含手续费）

---

**第三个月至今：API中转**

朋友推荐了LLM-Link，我测试了一周，确认模型是真实的Claude之后开始用。

切换原因：
- 支付宝直充，¥1=$1，没有汇率手续费
- 网络稳定性比直连好（国内节点优化过）
- 有阶梯首充活动，充¥100实际到账$140额度

最近一个月账单：消耗了$152额度，实际充值花了¥138（叠加首充赠送）。

对比第二个月：同等使用量，实际支出从¥1250降到¥138。

---

### 差距这么大的原因

主要是两点：

**1. 首充赠送活动叠加**

LLM-Link现在有阶梯首充赠送：
- 充¥100 → 到账$140额度（赠送40%）
- 充¥200 → 到账$320额度（赠送60%）
- 充¥500 → 到账$1000额度（赠送100%）

相当于折扣价拿额度，用量大的充¥200-500档最划算。

**2. Prompt Caching抵消了大量成本**

Claude API有Prompt Caching机制，重复的系统提示词和上下文命中缓存后只收取10%费用。

我的使用场景（同一个代码库反复操作），缓存命中率约65%，这一块省了非常多。

### 配置教程（5分钟搞定）

**Step 1：注册账号**

需要邀请链接注册：https://www.llm-link.top/register?aff=3Us3

**Step 2：创建Token**

登录后台 → 令牌管理 → 新建令牌 → 选择分组

> Claude Code用户选 **cc-sale** 分组，性价比最高。

**Step 3：配置Claude Code**

```bash
claude config set apiKey sk-你创建的token
claude config set baseUrl https://www.llm-link.top/v1
```

**Step 4：验证连接**

```bash
claude "你好，简单回复一下"
```

正常输出说明配置成功。

**常见问题：**

Q：报错"model not found"怎么办？
A：检查分组是否选对，cc-sale分组只支持Claude系列模型。

Q：流式输出中断怎么办？
A：在令牌设置里确认"支持流式输出"已开启。

Q：和官方API有什么区别？
A：转发到官方API，模型完全一样。可以让Claude报告自己的model name验证。

### 什么时候不适合用中转

说几个诚实的情况：

- **企业生产环境**：建议直连官方，合规和稳定性优先
- **轻度使用（每天<30分钟）**：官方Pro $20/月可能更划算
- **对数据隐私要求极高**：中转会经过第三方服务器

这篇主要针对**重度API用户**，如果你每天用量不大，不必折腾。
