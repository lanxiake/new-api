# 标题
聊几个能让 Claude Code Token 用量降三成的小习惯

# 分区
技术分享（或：经验）

# 正文

用 Claude Code 用了几个月了，工具是真好用，但每月账单也是真的肉疼。前段时间专门花了几个周末做对比实验，看哪些习惯真的能省 token、哪些只是看上去省。最后总结出五条，我这边稳定能压下去 25–35% 的用量，写出来给同样在烧钱的朋友参考。

不是什么"prompt engineering 黑魔法"，全是一些可以马上用的小动作。

---

### 一、项目根目录放一个 CLAUDE.md

Claude Code 启动时会自动读 `CLAUDE.md`，把里面的内容当作长期上下文。没这个文件的话，每开一个新会话，Claude 都会自己探索一遍项目——开几个文件确认结构、验证一下语言版本——这部分纯粹是 token 浪费。

我现在用的最小模板大概长这样：

```markdown
# Project: <项目名>

## 技术栈
- Go 1.22 / TypeScript 5
- Gin / React 19
- PostgreSQL + GORM

## 目录
- controller/ — HTTP handler
- service/    — 业务逻辑
- model/      — 数据模型

## 约定
- JSON 序列化用 common.Marshal，禁止直接 encoding/json
- 新代码必须能过 go vet
```

我在一个 20w 行的 Go 项目里放上之后，第一次消息的 token 从 8K 左右掉到 3K 左右，就靠 Claude 不再做"探索性读文件"。

注意控制行数在 200 行以内，再多 Claude 反而要先花 token 总结这个文件本身，得不偿失。

---

### 二、一个会话只做一件事，做完就 /clear

如果你一开会话就甩"帮我重构 auth、顺便加个 OAuth、再修一下限流"，Claude 会把这三个目标全程带在 context 里，后面每条消息都为这个三任务上下文付钱。

改成"一会话一任务，完事就 /clear"之后，token 消耗曲线立刻平了。再也不会出现"为啥第 20 条消息和前 10 条加起来差不多贵"的诡异账单。

如果你确实需要跨任务连续性，把上一个任务的 3 行结论写进 `CLAUDE.md` 就够了，比把完整对话历史拖在 context 里便宜多了。

---

### 三、用满 Prompt Caching

主流的 Anthropic 兼容 API 都支持 prompt caching：固定的前缀（system prompt、文件内容、项目上下文）会被缓存 5 分钟，写入时多花一点点钱，后续读取大概是正常价的 10%。

让 caching 真正生效，三条经验：

- **session 中间不要改 CLAUDE.md**——一改，缓存全失效
- **追加而不是重写**：跟进的时候说"再处理一下 X"，不要把完整 prompt 重新写一遍
- **长文件粘一次就够了**，后续用"刚才那段代码"、"上面那个函数"指代，不要再粘第二遍

我这边 200K token 的项目上下文，cache 命中率稳定 70% 左右，输入成本从 $0.60 一会话压到 $0.18 左右。

---

### 四、能用 Read 工具就别往 prompt 里粘代码

两种给 Claude 文件的方式：

```
A) "这是文件内容：<粘 5000 行>"
B) "Read src/foo.go"
```

效果差不多，但 (B) 便宜得多——Claude 真正用到的时候才读，而且经常只读一段 50 行的切片，而不是整个文件。(A) 那种粘进去之后，5000 行你都已经付钱了，不管 Claude 用没用。

心理上要克服一个习惯：别"主动帮 Claude 准备好一切"，让它自己按需要拉取就行。

---

### 五、不重要的活儿换便宜模型

写个单元测试，真不需要 Opus。机械性任务一律降级：

- 模板代码生成
- 加日志
- 整文件改名
- 简单测试用例

Claude Code 是支持 session 内切模型的。我这边 Sonnet 处理了大概 70% 的日常修改，Opus 只留给真正硬的问题——架构决策、复杂 bug、跨模块重构。

百万 output token 大概差价：

- Opus 4.7：$75
- Sonnet 4.5：$15
- Haiku 4：$5

70% 的常规活儿便宜 5–15 倍，这才是月度账单实质性下降的来源。

---

### 一些试过但没用的方法

- **手动"压缩" prompt**：花的精力不少，省的 token 不多，而且 Claude 经常错过被压缩掉的关键细节，得不偿失。模型自己判断要读什么比你判断更准。
- **极便宜的"Opus" 中转**：试过两家便宜得离谱的，结果都是国产模型挂着 Opus 的名字。代码质量立刻下降。一个简单原则：价格便宜得超过 5 倍，基本就是掺水。
- **关掉 prompt caching 来"保持最新上下文"**：缓存本来就会因为 context 变化自动失效，关掉只是单纯让自己更贵。

---

### 总结

| 习惯 | 节省幅度 |
|-----|---------|
| 项目根放 CLAUDE.md | 首条消息省 20–30% |
| 一会话一任务 + /clear | 长会话省 10–20% |
| 用 prompt caching | 跟进消息省 30–60% |
| 用 Read 工具不粘代码 | 文件密集任务省 10–30% |
| Sonnet/Haiku 干常规活 | 这部分省 5–15 倍 |

加起来我现在的月度账单大概是之前的三分之一，输出量没变，而且 Claude 表现还更稳定了（context 不臃肿，没那么容易跑偏）。

有什么你那边验证过有用的小技巧也欢迎回帖交流，互相学习。
